# 搜索双路径与 AI 聚合模式方案

> 状态：执行方案  
> 日期：2026-06-20  
> 范围：`legado-hub` 搜索页、阅读端搜索、AI 聚合源、搜索缓存与运行态任务  
> 结论：直接重构，不做兼容；数据库重建；废弃“缓存先回 + 实时补充”旧方案

---

## 1. 背景

当前搜索链路已经暴露出三个结构性问题：

1. 普通书源结果与 AI 聚合结果混在同一个结果池里，导致语义不清。
2. AI 聚合项依赖实时变化的候选分组，容易出现“先出现、后消失、再出现”的抖动。
3. 旧方案把缓存放在真实搜索之前，导致搜索结果的真相源不稳定，前端也难以向用户解释当前看到的是旧结果还是新结果。

本轮设计目标不是继续修补旧搜索链路，而是直接定义新的搜索模型：

1. **普通书源搜索路径** 与 **AI 聚合搜索路径** 分离。
2. **缓存不再优先返回**，而是在站点失败、超时、无返回时做站点级回退。
3. **前端结果表不再显示“缓存”字段**，只通过“获取时间”颜色弱提示历史结果与实时结果。
4. **搜索默认混合匹配书名与作者**，不再让用户手动切换“按书名 / 按作者”。

---

## 2. 本轮结论

### 2.1 旧方案直接废弃

以下旧方向全部废弃，不再继续实现：

1. 先查搜索缓存再发真实搜索。
2. 普通书源结果和 AI 聚合结果共用同一结果表直接混排。
3. 前端手动切换“按书名 / 按作者”两种搜索模式。
4. 把 `resultSource/cacheHit` 作为最终展示语义。

### 2.2 数据库直接重建

由于缓存模型和搜索路径都会重写，本轮建议：

1. 停止后端服务。
2. 删除旧数据库。
3. 用新 schema 重新初始化。

不做平滑迁移，不保留旧搜索缓存主路径兼容。

---

## 3. 总体原则

### 3.1 搜索分两条路径

搜索页和阅读端后续统一分为两条路径：

1. **普通书源搜索路径**
   - 只返回普通书源结果
2. **AI 聚合搜索路径**
   - 只返回 AI 聚合结果

两条路径可以共享底层普通源搜索能力，但对外返回结构、结果展示和缓存策略必须明确区分。

### 3.2 AI 聚合是显式模式，不是普通搜索副产品

AI 聚合不应再作为普通搜索结果里的“动态插入项”出现。

它必须满足：

1. 只有用户在搜索页显式点了 `书源聚合` 按钮或开关后才启用。
2. 启用后，前端结果表不再展示普通书源单条结果。
3. 后端内部仍然先执行一次普通书源搜索，再对普通源结果做 AI 聚合。

### 3.3 缓存只做站点级回退

缓存不再承担“首屏来源”的职责。

新规则：

1. 先真实搜索。
2. 若某个站点超时、失败、无返回。
3. 再尝试使用该站点历史缓存书籍结果补位。

也就是说，缓存是**站点级 fallback**，不是搜索起点。

### 3.4 用户感知弱化缓存

用户不需要在结果表里看到“缓存命中”字样。

前端只需要：

1. 显示这是普通书源结果还是 AI 聚合结果。
2. 通过“获取时间”的颜色弱提示这条普通结果是实时返回还是站点缓存回退。

## 4. 新搜索路径设计

## 4.1 普通书源搜索接口

建议新增或重定义为：

```text
/api/console/search/source
/api/legado/search/source
```

职责：

1. 只返回普通书源结果。
2. 不返回 AI 聚合结果。
3. 站点失败时允许用该站点历史缓存补位。

执行顺序：

1. 接收搜索请求。
2. 选择普通书源集合。
3. 执行真实搜索。
4. 对每个站点：
   - 成功：写入实时结果
   - 超时 / 失败 / 无返回：尝试该站点历史缓存结果
5. 汇总并排序。
6. 返回普通书源结果。

### 4.1.1 返回结构

建议：

```json
{
  "implemented": true,
  "keyword": "剑宗外门",
  "jobId": "search_xxx",
  "status": "running|completed|timed_out|failed|cancelled",
  "items": [
    {
      "displayType": "source",
      "freshness": "live",
      "name": "剑宗外门",
      "author": "其声喵喵然",
      "sourceId": "xbiquzw_net",
      "sourceName": "笔尖中文",
      "fetchedAt": "2026-06-20T14:50:18Z"
    }
  ],
  "debug": {
    "liveSearchPending": true
  }
}
```

其中：

- `displayType=source` 表示普通书源结果
- `freshness=live|cached` 仅供前端弱提示，不作为独立列主展示

## 4.2 AI 聚合搜索接口

建议新增或重定义为：

```text
/api/console/search/aggregate
/api/legado/search/aggregate
```

职责：

1. 只返回 AI 聚合结果。
2. 前端启用 `书源聚合` 模式时才调用。

执行顺序：

1. 接收搜索请求。
2. 在后端内部先跑一轮普通书源搜索流程。
3. 普通书源搜索的输入和调度规则与普通搜索接口保持一致。
4. 以普通源结果作为 AI 聚合输入。
5. 输出仅保留 AI 聚合结果。

### 4.2.1 返回结构

```json
{
  "implemented": true,
  "keyword": "我真不想重生啊",
  "jobId": "aggregate_search_xxx",
  "status": "running|completed|timed_out|failed|cancelled",
  "items": [
    {
      "displayType": "aggregate",
      "name": "我真不想重生啊",
      "author": "柳岸花又明",
      "sourceId": "legadohub_ai_aggregate",
      "sourceName": "LegadoHub AI聚合",
      "fetchedAt": "2026-06-20T14:50:18Z"
    }
  ],
  "debug": {
    "liveSearchPending": true,
    "sourceSearchPhaseCompleted": false,
    "aggregatePhaseStarted": false
  }
}
```

## 5. 搜索页模式切换

### 5.1 前端新增按钮

搜索页新增：

- `普通书源`
- `书源聚合`

或等价的开关按钮：

- 默认关闭：普通书源模式
- 打开后：AI 聚合模式

### 5.2 模式行为

#### 普通书源模式

1. 调用普通书源搜索接口。
2. 结果表仅显示普通书源结果。

#### 书源聚合模式

1. 调用 AI 聚合搜索接口。
2. 结果表不再显示普通书源单条结果。
3. 结果表只显示 AI 聚合项。
4. 进度区/日志区继续显示：
   - 普通源搜索阶段
   - 聚合阶段

### 5.3 为什么保留进度区里的普通源过程

因为搜索页本身就是调试页。

AI 聚合模式下，虽然结果表不展示普通源单条结果，但进度和日志保留普通源过程有三个价值：

1. 能看见哪些站点被调用。
2. 能看见哪些站点失败或超时。
3. 能判断 AI 聚合结果是建立在哪些普通源基础上的。

## 6. 缓存策略重定义

### 6.1 废弃“缓存先回”

旧规则：

1. 先搜缓存
2. 再搜实时

直接废弃。

### 6.2 新规则：站点级回退

新规则：

1. 先真实搜索。
2. 对每个站点独立判断。
3. 若该站点：
   - 超时
   - 失败
   - 无返回
4. 则尝试该站点历史缓存中的书籍结果补位。

### 6.3 缓存表建议继续使用书籍实体缓存

缓存真相源仍然建议保留：

```text
book_search_cache
```

但它的用途不再是“首轮返回”，而是：

1. 普通书源路径中的站点级 fallback
2. AI 聚合路径中作为普通源输入的补位手段

### 6.4 TTL

缓存 TTL 保持：

- 7 天

---

## 7. 搜索匹配规则重定义

### 7.1 不再前端二选一

前端不再让用户手动选：

- 按书名
- 按作者

### 7.2 默认混合搜索

统一搜索规则：

1. 同时考虑书名和作者。
2. 使用统一归一化。
3. 对不同命中方式赋不同权重。

### 7.3 建议权重

建议排序权重：

1. 书名完全命中：最高
2. 书名包含命中：高
3. 作者完全命中：中高
4. 作者包含命中：中
5. 书名 + 作者同时命中：额外加分
6. 站点缓存回退结果：在同站实时结果之后排序

### 7.4 去重

普通源结果去重优先级：

1. `source_id + raw_book_url`
2. 若缺地址，再退化为 `normalized_name + normalized_author + source_id`

---

## 8. 展示字段重定义

### 8.1 字段语义

建议统一为：

```json
{
  "displayType": "source|aggregate",
  "freshness": "live|cached"
}
```

含义：

- `displayType=source`
  - 普通书源结果
- `displayType=aggregate`
  - AI 聚合结果
- `freshness=live`
  - 真实搜索得到
- `freshness=cached`
  - 站点失败时用历史缓存补位

### 8.2 前端展示规则

普通书源结果：

1. 不单独显示“缓存”列
2. `fetchedAt` 保留
3. 根据 `freshness` 改变获取时间颜色

建议：

- `live`
  - 绿色
- `cached`
  - 灰绿或弱化色

AI 聚合结果：

1. 不显示 `freshness`
2. 只显示这是 AI 聚合结果

---

## 9. AI 聚合结果生成规则

### 9.1 不再动态插入普通结果表

AI 聚合项不再作为普通搜索结果中的临时插入项出现。

### 9.2 聚合输入

AI 聚合接口的输入是：

1. 普通源实时命中结果
2. 普通源站点级缓存补位结果

但只有在后端完成一次普通源搜索后，才进入聚合阶段。

### 9.3 聚合输出

AI 聚合接口只输出：

- `displayType=aggregate`

不输出普通源结果。

### 9.4 稳定性原则

AI 聚合项一旦进入结果表，不应随着普通源实时增量结果来回闪烁。

建议：

1. 等普通源阶段达到最低稳定门槛后再生成聚合结果
2. 或生成后只允许更新内容，不允许中途删除整条聚合项

最低稳定门槛建议之一：

1. 至少 2 个普通源命中同一本书
2. 且核心字段一致度满足要求

## 11. 实施顺序

### 阶段 1：接口拆分

1. 新增普通搜索接口
2. 新增 AI 聚合搜索接口

### 阶段 2：缓存策略切换

1. 删除缓存先回主路径
2. 改成站点级缓存回退

### 阶段 3：匹配规则切换

1. 去掉前端 title/author 二选一
2. 改成默认混合匹配和统一排序

### 阶段 4：前端模式切换

1. 新增 `书源聚合` 按钮

### 阶段 5：展示语义切换

1. 引入 `displayType`
2. 引入 `freshness`
3. 删除“缓存”列

1. 普通模式只显示普通源结果
2. AI 聚合模式只显示 AI 聚合结果
3. AI 聚合模式进度区仍能看到普通源搜索过程
4. 普通源失败时缓存能补位
5. 结果表不再混杂和闪烁

3. 不显示“缓存”字段

1. 结果表只显示 AI 聚合结果
2. 普通源结果不出现在结果表里
3. 进度和日志区仍显示普通源搜索阶段
4. AI 聚合项不再反复出现/消失

### 混合搜索

1. 书名命中能召回
2. 作者命中能召回
3. 双命中排序更高
4. 前端无 title/author 手动切换

---

## 13. 最终收口

本轮最终结论只有五句：

1. **搜索拆成普通书源路径和 AI 聚合路径两个接口。**
2. **AI 聚合只在显式开启 `书源聚合` 模式后执行。**
3. **缓存不再先回，只做站点级失败回退。**
4. **搜索默认混合书名和作者，不再让用户手动切模式。**
5. **前端通过 `displayType` 与 `freshness` 组织展示，去掉“缓存”列。**
