# 共享订阅式聚合书库方案

> 状态：执行方案
> 日期：2026-06-23
> 范围：legado-hub 订阅页、书库页、阅读端搜索注入、管理员后台、聚合章节处理、任务重建与追踪
> 结论：废弃“即时 AI 聚合搜索入口”，改为“MoviePilot 风格的共享订阅书库 + 后台持续处理 + 阅读端普通搜索注入”

---

## 1. 背景与目标

当前“搜索时即时生成 AI 聚合书”的方案存在四个根问题：

1. 聚合结果依赖单次搜索现场状态，书会闪烁、混杂、抖动。
2. 搜索、聚合、正文处理耦合在同一链路里，响应慢且难维护。
3. 阅读端拿到的是临时聚合结果，不是长期可维护的本地书库对象。
4. 管理后台旧有的“聚合书源 / 聚合书架 / 验证”三条入口已经和新的产品方向冲突。

本方案改为：

1. 提供一个**订阅页**，按“书”聚合卡片搜索，而不是按“源”搜索。
2. 任意普通用户可以把一本**尚未入库**的书加入全局书库。
3. 一本书一旦进入书库，就变成**全局共享本地资产**，后续由后台持续处理。
4. 阅读端仍然走普通搜索，但会按匹配规则把本地书库中的聚合书注入结果。
5. 管理员后台负责验证搜索效果、管理书库、管理任务、管理用户和系统参数。

产品抽象参考 [MoviePilot](https://github.com/jxxghp/MoviePilot)：

1. 搜索结果是一媒体一卡片，这里对应为“一本书一卡片”。
2. 订阅后创建长期对象，并由后台持续处理。
3. 本地库是长期资产，搜索和管理都围绕本地库展开。

## 2. 角色与入口

### 2.1 普通用户

普通用户只有两类页面：

1. `订阅`
2. `书库`

普通用户权限：

1. 可以在订阅页搜索书籍。
2. 可以把**尚未入库**的书加入全局书库。
3. 首次加书时只允许设置 `startChapterIndex`。
4. 可以查看全局书库与“我添加的”书。
5. 不允许修改任何全局处理参数。
6. 不允许暂停、恢复、归档、删除、重建。
7. 如果书已经入库，只能看到“已入库”，不能重复添加。

### 2.2 管理员

管理员后台导航固定为：

1. `仪表盘`
2. `书源`
3. `搜索`
4. `订阅`
5. `书库`
6. `缓存`
7. `用户`
8. `设置`

其中：

1. `书源` 内部分为两个 tab：
   - `官方源`
   - `第三方源`
2. `搜索` 只用于**验证阅读端最终搜索效果**。
3. `订阅` 是管理员可操作的书籍订阅卡片页。
4. `书库` 是全局书库和书籍管理入口。
5. `用户` 用于创建用户、重置密码、禁用用户。

### 2.3 已废弃页面

以下旧页面和旧路由直接删除，不做兼容跳转：

1. `聚合书源`
2. `聚合书架`
3. `验证`

## 3. 三类搜索面的职责

### 3.1 订阅页搜索

订阅页搜索是**按书聚合后的卡片搜索**，不是多源调试搜索。

规则：

1. 一本书只显示一张卡片。
2. 卡片以**官方源元数据优先**：
   - 有官方源时，封面、作者、简介、章节数、完结状态优先取官方源。
   - 无官方源时，取综合分最高的第三方源。
3. 搜索结果以**瀑布流卡片 + 无限滚动**形式展示。
4. 搜索结果支持**实时增量出卡片**，但卡片 ID 必须稳定，只允许补字段和补状态，不允许闪烁删除重建。
5. 如果命中已入库书，订阅页折叠成一张“已入库”卡片，不再展示多个源候选。

订阅页卡片按钮只出现在这里，不出现在调试搜索页：

1. `订阅`
2. `查看`
3. `管理`

权限：

1. 普通用户：
   - 未入库：显示 `订阅`
   - 已入库：显示灰色 `已入库`
   - `查看` 可用
   - `管理` 不可用
2. 管理员：
   - 未入库：显示 `订阅`
   - 已入库：显示 `查看`、`管理`

### 3.2 阅读端普通搜索

阅读端继续走**普通搜索**，不提供订阅入口，不走登录态。

规则：

1. 普通源结果正常返回。
2. 本地书库命中时，按匹配规则注入 `legadohub_ai_aggregate` 结果。
3. 注入规则是**按书名/作者匹配命中**，不是把本地所有书都塞进去。
4. 本地聚合书与普通源结果**同时展示**。
5. 本地聚合书排序按“官方源同档加权”处理，默认 `+50`。

### 3.3 订阅搜索

订阅搜索只负责**官方源发现**，不承担第三方源发现与补充。

规则：

1. 只搜索官方源，不搜索第三方源。
2. 结果只生成官方候选卡片，不展示第三方补充卡片。
3. 官方源按站点优先级与源可用性排序，优先返回最可能命中的官方入口。
4. 搜索接口应尽快返回首批官方结果，后续官方源完成后再继续轮询刷新。
5. 第三方源不进入订阅发现阶段，后续只作为章节补全与重聚合阶段的输入来源。
6. 若官方源全无命中，订阅搜索直接结束，不降级为第三方发现。
7. 订阅阶段不暴露第三方源选择器，避免把发现阶段和补全阶段混在一起。

后台补源规则：

1. 用户点击订阅后，入库 payload 可以只有官方源。
2. 首轮聚合任务开始时，如果该书还没有第三方候选源，由聚合任务按书名 / 作者在后台搜索第三方源。
3. 第三方搜索结果只接受同名同作者命中，写入 `aggregate_book_sources`，并同步合并进 `aggregate_payload_json.sources`。
4. 后台补源不计入订阅搜索前台进度，不生成订阅搜索卡片。
5. 为兼顾至少 50 人同时使用的场景，首轮后台补源只搜索优先级最高的一小批第三方源；后续可由定期重聚合任务继续扩展候选池。

### 3.4 管理员后台搜索

管理员后台搜索页与阅读端逻辑保持一致，用于验证“阅读端会看到什么”。

规则：

1. 搜索结果保留多源普通搜索形态。
2. 按与阅读端相同的规则注入本地聚合书。
3. 不显示 `订阅 / 查看 / 管理` 三个动作按钮。
4. 该页面只用于调试和验证搜索效果，不承担订阅入口职责。

## 4. 全局书库对象模型

### 4.1 共享书对象

系统以**全局共享书对象**为中心。

约束：

1. 一本入库书只有一个稳定的 `aggregate_book_id`。
2. `aggregate_book_id` 是不透明稳定 ID，不从书名或 source 列表动态拼接。
3. 一本书一旦入库，就是全局共享本地资产。
4. 后续任何用户看到的都是同一个本地库对象与同一套处理结果。

### 4.2 书籍身份匹配

共享书匹配采用多字段模型：

1. 官方作品 ID 优先。
2. 再看 `canonical_name + canonical_author`。
3. 管理后台保留人工 `合并 / 拆分` 能力。

禁止的旧做法：

1. 用 `novel_name` 作为唯一键。
2. 用 source 列表拼接身份。
3. 按目录名承担真正主键语义。

## 5. 用户后台信息架构

### 5.1 订阅页

订阅页是新增全局书的唯一普通用户入口。

卡片字段：

1. 封面
2. 书名
3. 作者
4. 简介
5. 字数
6. 章节数
7. 完结状态
8. 来源概览
9. 当前是否已入库
10. 添加人
11. 当前处理进度

### 5.3 订阅入库配置对象

用户点击 `订阅` 后，系统创建一份稳定的订阅配置对象，作为后续整本处理、追更、补源与补全的唯一真相源。

第一版必须随订阅对象一起固化的字段：

1. `cover_url`
2. `display_name`
3. `display_author`
4. `intro`
5. `book_status`
6. `total_chapters_at_subscribe`
7. `start_chapter_index`
8. `auto_archive_on_complete`
9. `settings_json`
10. `primary_source_id`
11. `primary_source_name`
12. `primary_book_url`
13. `primary_book_id`
14. `primary_toc_url`
15. `supplement_source_config_json`

其中：

1. `primary_book_url` 是主源书籍详情页地址，后续章节补抓、重建与人工核对都以它为稳定入口。
2. `supplement_source_config_json` 第一阶段可以为空对象，但字段必须预留，用于后续写入第三方源候选地址、匹配策略、补全状态。
3. `settings_json` 第一阶段只承载对整本抓取生效的基础选项，不提前塞入 AI 续写之类尚未实现的选项。

### 5.2 书库页

用户书库页保留两个视图：

1. `全局书库`
2. `我添加的`

其中“我添加的”只按 `added_by_user_id = current_user` 过滤，不依赖 `user_subscriptions`。

`查看` 打开一个**轻量书籍详情弹窗**。

该弹窗和当前后台“查看详情”逻辑合并，但收缩成轻量模式：

1. 封面
2. 书名
3. 作者
4. 简介
5. 处理进度
6. 目录

### 6.2 目录与试读

详情弹窗中的目录只用于浏览、选中和双击进入试读。

规则：

1. 不单独放“试读”按钮。
2. 单击目录章节只做选中，不跳转页面。
3. 双击目录章节，进入现有后台阅读页面。
4. 未处理章节在目录中可见；如果双击进入阅读页，则正文区域返回占位提示。

### 6.3 管理

`管理` 不在弹窗里做，直接跳转到书库管理页。

## 7. 章节处理顺序与可搜索门槛

### 7.1 首次入库

普通用户首次加书时，只允许设置：

1. `startChapterIndex`
2. `autoArchiveOnComplete`

其他参数全部走系统默认值：

1. 自动追更：开启
2. 更新检查间隔：60 分钟
3. 主源策略：官方优先，第三方综合分数兜底
4. AI 聚合：开启
5. AI 净化：开启
6. 自动归档：默认开启，可由首次加书用户关闭

补充说明：

1. 订阅创建时必须同时写入封面、书名、作者、简介、连载状态、订阅时章节总数与主源书籍页地址。
2. 订阅对象必须保留后续第三方补源配置挂点，但第一阶段不要求第三方地址已经齐备。

### 7.2 顺序处理模型

一本书创建后立刻开始处理。

规则：

1. 从 `startChapterIndex` 开始，**严格顺序向后处理**。
2. 第一阶段必须先确保从 `startChapterIndex` 到当时主源最新章的全部章节都完成本地抓取。
3. `startChapterIndex` 之前的章节先标记为 `placeholder`。
4. 真实正文文件只在章节处理完成后写入。
5. 不创建空的占位正文文件。
6. 目录完整可见，占位章也显示在目录中。
7. 点击占位章只返回提示，不提权重排队。
8. 如果主源 VIP 章节只能拿到预览内容，第一阶段也必须照样落盘，不允许因为“只有预览”而跳过章节。
9. 每个章节正文文件末尾必须附加额外信息块，至少记录：
   - 主源章节对应地址
   - 章节真正总字数
   - 当前章是否仅为预览内容

### 7.3 连载书回填规则

如果书是连载中的：

1. 先处理从 `startChapterIndex` 到“订阅时快照的最后一章”这一段。
2. 当这段完成后，开始回填 `startChapterIndex` 之前的旧章节。
3. 后续新增章节与前置旧章节并行穿插处理。
4. 只要书未完结且未归档，系统必须持续自动检查主源更新并抓取新章节。
5. 只有当书被官方/主源明确判定为完结，或者管理员手动归档时，自动追更才停止。

### 7.4 搜索可见门槛

一本书允许进入阅读端普通搜索的条件是：

1. TOC 已完成。
2. 从 `startChapterIndex` 开始，**连续可读 50 章**。

注意：

1. 这个 50 章门槛只按 `startChapterIndex` 往后计数。
2. 不要求前置旧章节已经回填。
3. 不要求最新章节正文已经处理成功。
4. 如果从 `startChapterIndex` 到当前末章总数不足 50 章，则该区间全部处理完成后，也允许进入搜索。

### 7.5 最新章节策略

最新章节只探测**元数据**，不抢先处理正文。

搜索卡片展示：

1. `源站最新章节`
2. `本地已处理到第 X 章`

## 8. 本地书库搜索注入规则

### 8.1 注入范围

本地书库参与普通搜索时，必须仍按书名/作者匹配命中，不允许全量注入。

### 8.2 排序

本地聚合书：

1. 与普通源结果同时展示。
2. 排序时享受与官方源同档的固定加权，默认 `+50`。
3. 不做绝对置顶。

### 8.3 归档书

已归档书仍继续参与普通搜索注入，只是不再自动更新。

## 9. 生命周期与管理员状态

### 9.1 普通用户行为

普通用户只负责把书加入全局书库。

书一旦入库：

1. 后续生命周期不再由普通用户控制。
2. 普通用户不能删除、暂停、归档、重建。

### 9.2 管理员状态

管理员管理状态固定为三种：

1. `暂停`
2. `归档`
3. `删除`

定义：

#### 暂停

1. 临时停止处理与更新。
2. 书仍可搜索、可阅读。

#### 归档

1. 永久停止自动更新。
2. 书继续作为本地书库资产保留。
3. 仍可搜索、可阅读。

#### 删除

1. 从全局书库移除。
2. 清理章节文件、任务、来源快照、追踪信息。

### 9.3 自动归档

如果 `autoArchiveOnComplete = true`，书籍被判定为完本后自动归档。

完本判定规则：

1. 优先以官方主源返回的完结状态为准。
2. 没有官方主源时，以当前主源返回的完结状态为准。
3. 只有在最近一次成功更新后仍判定为完本，才执行自动归档。
4. 如果 `autoArchiveOnComplete = false`，则完本后不自动归档，而是标记为“等待管理员归档”，继续保留在书库中，直到管理员手动执行归档。

## 10. 管理员修改任务的三类语义

### 10.1 即时生效，不重跑

适用于：

1. 暂停 / 恢复
2. 更新检查间隔
3. 自动追更开关
4. 立即重试某章
5. 立即重查 TOC

### 10.2 前向生效，不回刷旧章

适用于：

1. AI 聚合开关
2. AI 净化开关
3. 候选源优先级
4. 主源偏好策略

规则：

1. 已处理章节不改。
2. 未处理章节按新规则继续处理。
3. 管理后台需要能看到该书存在多批次处理策略。

### 10.3 重建

适用于：

1. 修改 `startChapterIndex`
2. 管理员明确要求整本按新规则重做
3. 需要整书一致性时

重建规则：

1. 停止旧任务。
2. 清空旧的最终章节产物和章节状态。
3. 重建 TOC、占位状态和处理队列。
4. 优先重新抓取当前源内容。
5. 抓不到时，再回退旧来源快照。
6. 不直接复用旧 AI 输出正文。

---

## 11. 来源快照与章节追踪

### 11.1 来源快照

每章每来源只保留一份**最新干净快照**。

“干净快照”的定义：

1. 保存插件清洗后的来源正文文本与元数据。
2. 不保存原始 HTML。

每份快照至少包含：

1. `source_id`
2. `source_chapter_id`
3. `chapter_index`
4. `title`
5. `clean_content`
6. `content_hash`
7. `classification`
8. `fetched_at`

### 11.2 本地章节尾注追踪块

每个生成的本地章节文件末尾追加一段固定标记的 YAML/纯文本追踪块：

1. `LEGADOHUB_TRACE_BEGIN`
2. `LEGADOHUB_TRACE_END`

内容至少记录：

1. `aggregateBookId`
2. `chapterIndex`
3. `policyVersion`
4. `processedAt`
5. `startChapterIndex`
6. `autoArchiveOnComplete`
7. `primarySource`
8. `primarySourceChapterUrl`
8. `candidateSources`
9. `selectedSource`
10. `selectedContentSource`
11. `aiAggregateEnabled`
12. `aiPurifyEnabled`
13. `modificationTrail`
14. `sourceHashes`
15. `finalContentHash`

其中 `modificationTrail` 需要能表达：

1. 原始来源是谁
2. 聚合补全来源是谁
3. 做了哪些清洗/净化/替换
4. 哪一步使用了 AI
5. 当前章是按哪一版策略产生的

第一阶段附加要求：

1. 如果章节只有主源预览内容，`modificationTrail` 必须明确标记为 `preview_only_from_primary_source`。
2. `sourceHashes` 之外还要保留 `sourceWordCount` 或等价字段，表达该章在主源上的真实总字数。

### 11.3 阅读端输出

阅读端返回正文时必须自动过滤整个追踪块，只让用户看到纯正文。

## 13. 阅读端接入

阅读端不走登录态。

规则：

1. `/api/legado/source`
2. `/api/legado/search`
3. `/api/legado/book/*`
4. `/api/legado/chapter/*`

均按匿名共享书库能力设计。

因此：

1. 生成的 LegadoHub 源不要求用户登录。
2. 如果保留 `loginUrl` 字段，它只作为用户后台入口快捷跳转，不承担认证语义。
3. 阅读端直接读取共享本地书库结果。

## 14. 实施顺序

### 阶段 0：订阅配置模型收口

1. 统一订阅对象字段，固定写入封面、书名、作者、简介、连载状态、订阅时章节总数、起始章节、主源书籍页地址。
2. 为后续第三方补源保留 `supplement_source_config_json`。
3. 让入库 payload 成为后续抓取、追更、补全与归档的唯一真相源。

### 阶段 1：路由与导航清理

1. 删除 `聚合书源 / 聚合书架 / 验证` 页面与路由
2. 重建管理员后台导航
3. 重建用户后台导航

### 阶段 2：数据模型重构

1. 新增 `aggregate_books`
2. 新增 `aggregate_book_sources`
3. 扩展 `aggregate_chapter_tasks`
4. 新增 `aggregate_operation_logs`
5. 不再新增 `user_subscriptions`

### 阶段 3：订阅页

1. 新增书卡片搜索接口
2. 官方元数据优先聚合
3. 实时增量卡片
4. 瀑布流布局
5. 无限滚动
6. 卡片详情弹窗

### 阶段 4：主源完整入库与持续追更

1. 全局书库页
2. 我添加的视图
3. 入库后立即 enqueue 聚合书任务，并启动首轮 bootstrap。
4. 第一阶段只要求从官方源或主源完整获取整本书籍信息与 TOC。
5. 从 `startChapterIndex` 开始顺序抓取全部章节到本地。
6. 主源 VIP 章节即使只有预览内容，也要完整落盘并带尾注信息块。
7. 每章尾注必须包含主源章节地址与章节真正总字数。
8. 首轮处理完成后，系统继续自动检查主源更新并抓取新增章节。
9. 自动追更持续到小说完结或管理员手动归档。
10. 第四阶段完成前，不做第三方章节补全，也不做 AI 净化 / AI 续写。

### 阶段 5：第三方 VIP 预览章节补全

1. 只针对第一阶段已落盘但标记为 `preview_only` 的章节。
2. 后台按书名 / 作者自动补充第三方源候选地址与章节来源。
3. 章节匹配允许章节序号中文/数字差异，采用“模糊标题 + 章节头部匹配”。
4. 仅当第三方补全结果可信时，才覆盖或合并原预览章节。
5. 补全过程必须保留主源正文、第三方正文和最终合并结果的追踪信息。

### 阶段 6：AI 后处理能力

1. 在主源完整入库和第三方补全都稳定后，再引入 AI 净化。
2. AI 去屏蔽词、AI 续写等能力只作为附加阶段，不阻塞前两阶段上线。
3. AI 后处理必须建立在完整章节文本基础上，而不是建立在预览正文上。

### 阶段 7：管理能力

1. 暂停 / 归档 / 删除
2. 参数修改三类语义
3. 重建流程
4. 策略版本与追踪块
5. 来源快照管理

### 阶段 8：阅读端搜索注入

1. 阅读端普通搜索注入本地书
2. 排序加权
3. 归档书继续参与搜索
4. 调试搜索页与阅读端对齐

## 15. 验证清单

1. 订阅页搜索结果是一书一卡片，而不是多源列表。
2. 订阅页命中已入库书时，显示单卡片 `已入库` 状态，不再重复可订阅。
3. 普通用户首次加书时只能设置 `startChapterIndex`。
4. 订阅对象已固化主源书籍页地址与后续第三方补全配置挂点。
5. 从 `startChapterIndex` 到当前主源末章的全部章节都已落盘，VIP 预览章也不会漏抓。
6. 每章正文文件末尾都包含主源章节地址和章节真正总字数。
7. 从 `startChapterIndex` 开始连续处理满 50 章后，该书开始进入阅读端普通搜索。
8. 目录里可以看到占位章，但没有真实正文文件。
9. 点击占位章不会提权，只返回提示。
10. 阅读端普通搜索不会注入全库，只会注入书名/作者匹配命中的本地书。
11. 本地聚合书和普通源结果同时展示，且本地书有 `+50` 同档加权。
12. 已归档书仍然能在阅读端普通搜索中出现。
13. 主源完结前会持续自动追更；主源完结或管理员归档后才停止。
14. 第三方补全只作用于预览章节，不会抢在主源完整入库之前执行。
15. AI 净化 / AI 续写等附加能力只会在前两阶段稳定后再接入。
16. 管理员修改 `startChapterIndex` 时，触发重建。
17. 重建优先重新抓当前源内容，失败时回退来源快照。
18. 本地章节文件末尾有追踪块，阅读端返回时已过滤。
19. 管理后台搜索页不再显示 `订阅 / 查看 / 管理` 按钮。
20. `聚合书源 / 聚合书架 / 验证` 三个旧入口已经删除。
21. 首次加书时可以设置 `autoArchiveOnComplete`；关闭后完本只进入“等待管理员归档”状态，不自动归档。
