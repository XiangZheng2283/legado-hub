# 多源句级校对与水印净化

> 状态：已实施
> 日期：2026-07-31
> 实施更新：2026-08-03
> 范围：第三方章节候选、多源一致性、句序异常、站点水印、正式正文发布
> 关联文档：`subscription-source-snapshot-rebuild-plan.zh-CN.md`

## 1. 评审目的

当前订阅链路使用官方预览、官方字数、第三方源快照和跨源正文相似度完成两类校验：

1. 标题、预览开头和字数都正常的第三方正文，仍可能存在正文句序错乱。
2. 多源模糊对齐发现双侧锚点之间的单源额外段，并在证据充分时生成派生净化正文。

句级校对用于章节级异常判定；严格三源证据用于剔除少量来源独有插入段。两项能力均不得绕过官方校验，不得跨源拼接正文，也不得自动重排正文。

正式正文始终派生自一份源快照；多源对齐画布只建立比较坐标，不提供拼接后的发布正文。

## 2. 与现行方案的关系

现行 `subscription-source-snapshot-rebuild-plan.zh-CN.md` 规定：

- 段级校对默认记录诊断；满足严格三源、双侧锚点和官方复核时可删除少量单源额外段。
- 句级校对只在至少两个顺序一致的参考来源共同证明异常时拒绝当前来源的当前章节。
- 双源、单侧锚点、大段差异和官方复核失败仍只产生证据，不自动删除。

句序拒绝和严格三源净化均已同步到原方案、实现、测试和更新日志。

2026-08-03 实施范围：

- 比较指纹执行 NFKC、繁简统一并去除排版空白和标点，不修改快照或发布正文。
- 单句阈值 `0.80`，最短有效句 6 字，局部窗口 `±3`，局部失败后才全局补偿。
- 至少匹配 10 句且覆盖率不低于 `65%` 才形成顺序证据。
- 两个参考来源的顺序比例不低于 `92%`，候选与两者的顺序比例均不高于 `80%`，且至少有 3 个错位和 3 次倒退时，标记 `rejected_order_mismatch`。
- 双源冲突、二对二冲突、证据不足和单纯插入句均不定责。
- 实时抓取和本地快照重建共用 `_select_consistent_candidate()`，审计写入 `source_alignment_json.sentenceOrder`。
- 段落比较执行 NFKC、OpenCC 繁转简、去标点空白和模糊匹配，转换结果只用于比较。
- 至少三个已通过官方门槛的来源参与，且两个参考来源同时支持差异段前后锚点，才允许删除。
- 连续删除最多 3 段且不超过正文字符数的 2%；章首、章末和句内差异不删除。
- 删除后重新校验官方预览与官方字数；删除内容与预览重叠、字数偏差变大或任一门槛失败时整次撤销。
- `rawContent` 和每源 `content` 快照保持不变，仅发布正文使用派生结果，审计写入 `source_alignment_json.lineConsensus`。

保持不变的边界：

1. 官方源仍是书籍身份、目录、章节标题、预览和字数的可信锚点。
2. 第三方源默认不可信，只能作为待验证候选。
3. 每份 `rawContent` 永久保留，任何净化均生成派生内容和审计记录。
4. 正式正文只能追溯到一份源快照；禁止跨源补句、拼段或重排。
5. 句序异常只拒绝当前源的当前章节，不封禁整个源。

第六十八章和第六十九章中的异常候选，标题、正文长度和开头内容均接近官方数据，仅靠标题、预览头和字数可能无法发现正文中后段错序。现有多源共识最终选择了正常来源，但没有将错序候选明确标记为章节级异常。

### 3.3 段落直接比较的局限

部分站点会在固定列宽处强制换行。同一句正文可能被拆成多个“段落”，导致段级算法把正常排版差异误判为大量来源独有段。

因此：

- 句级序列适合判断内容顺序。
- 段级结构适合生成维护证据和定位独立插入块。
- 原始换行不得直接作为自动删除依据。

## 4. 总体判定顺序

每个候选必须依次经过以下阶段：

1. 章节身份校验。
2. 官方预览校验。
3. 官方字数校验。
4. 多源句级顺序校验。
5. 多源水印证据校验。
6. 生成派生净化正文。
7. 再次执行官方预览和官方字数校验。
8. 写入正式章节和完整审计信息。

多源一致性只能在已经通过官方门槛的候选中决定选择和净化，不能让未通过官方校验的候选重新变为合格正文。

官方锚点缺失时，不得以多源一致代替官方门槛。应保留官方预览、待处理或失败状态。

## 5. 章节身份校验

候选进入正文比较前必须确认属于同一官方章节：

1. 优先使用完整章节标题相似度。
2. 章节序号只用于缩小搜索范围和排序，不能在双方都有明确副标题但副标题不同时单独证明同章。
3. 标题存在截断、繁简差异或感谢语差异时，可使用标题主体和官方预览共同确认。
4. 历史快照标题与当前官方标题不符时，不复用该快照；保留原文件供审计，重新匹配或重新抓取。

需要评审的关键点：现有“序号相差不超过 2 即可回退匹配”仍可能读取相邻错章，建议收紧为“至少一方缺少有效标题主体时才允许序号回退”。

## 6. 比较用句子序列

### 6.1 只影响比较的规范化

以下处理只生成比较指纹，不修改输出正文：

1. 统一 `CRLF` 和 `CR`。
2. 去除句内排版空白和站点固定列宽换行。
3. 统一全角/半角比较形式。
4. 可选地统一繁简、常见异体字和标点，仅用于匹配。
5. 保留原句文本、原始位置和原始标点，供最终审计引用。

不得把比较规范化后的文字直接作为正式正文，以免擅自改变用字、标点和作者表达。

### 6.2 句子切分

优先按中文句末标点、引号闭合和独立对话切分。过短片段与相邻句合并，避免单个语气词产生大量噪声。

建议初始参数，均为待评审值：

- 单句模糊匹配阈值：`0.80`
- 最短有效句：6 个规范化字符
- 局部搜索窗口：目标位置前后各 3 句
- 全局补偿搜索：仅在局部搜索失败时执行

## 7. 句序异常判定

句级匹配产生目标句到其他来源句子位置的映射。正常章节的映射应基本单调递增。

候选可标记为 `rejected_order_mismatch` 的必要条件：

1. 候选已经通过官方预览和官方字数门槛。
2. 至少两个其他来源对相同章节形成顺序一致的参考组。
3. 候选与参考组具有足够句子覆盖，排除“其实是另一章”的情况。
4. 匹配位置出现持续倒退、交叉或大范围跳转，而不是一两句正常版本差异。
5. 两个参考来源均支持该异常判断。

处理结果：

- 不自动重排异常候选。
- 不从异常候选中抽取部分正文。
- 只拒绝当前来源的当前章节。
- 保存匹配覆盖率、倒退次数、跳转位置和支持来源。
- 该来源仍可参与其他章节和后续更新。

双源之间出现顺序冲突时，无法仅凭两份文本证明哪一份顺序正确。此时必须扩展来源；没有第三份证据时不做错序定责。

## 8. 自动水印剔除

### 8.1 优先选择干净来源

如果多数参考来源已经存在完整、干净且通过官方门槛的正文，应直接选择其中一份，不必为了使用异常来源而执行净化。

自动剔除用于以下场景：候选整体质量合格，但包含少量、证据充分的来源独有插入句；保留该候选有明显水印，完全拒绝又会浪费可用正文。

### 8.2 可自动剔除的必要条件

只有同时满足以下条件，来源独有内容才可自动剔除：

1. 至少三个通过官方门槛的独立来源参与比较。
2. 待删除内容只存在于一个来源。
3. 至少两个其他来源在该位置前后的锚点句一致且顺序连续。
4. 待删除内容必须位于两个可靠锚点之间；正文首尾的单侧锚点不足以自动删除。
5. 待删除单位是完整句子或独立段落，不是句内猜测出的几个字。
6. 待删除内容不与官方预览中的任何句子匹配。
7. 删除后与多数来源的一致度提高。
8. 删除后重新通过官方预览和官方字数门槛，且不得比删除前更偏离官方字数。
9. 删除规模处于保守上限内；大段差异应拒绝候选或扩展来源，而不是自动删文。

单次自动删除上限固定为连续 1 至 3 个独立段落，且所有删除内容合计不超过候选正文的 2%。

### 8.3 明确禁止自动剔除

以下情况不得依据跨源差异自动删除：

- 只有两个来源。
- 其他来源可能是漏文、截断或付费预览。
- 差异内容出现在官方预览中。
- 前后锚点无法同时确认。
- 多个来源各自存在不同版本，未形成稳定多数。
- 差异是繁简、标点、错别字、分段或强制换行。
- 差异包含大段连续叙事，超过保守删除上限。
- 删除后虽更接近某个来源，但偏离官方字数。

双源情况下，已知插件专属水印仍可由插件精确规则或现有正则净化；不得把双源差异本身当作自动删除证据。

## 9. 候选选择规则

建议按章节建立动态候选池：

1. 先读取所有本地快照并执行官方门槛。
2. 候选不足时，并行请求首批三个来源。
3. 三源一致时选择与其他来源平均一致度最高、句序异常最少的候选。
4. 两源一致时允许发布，但不能执行基于多数的未知水印自动删除。
5. 三源不一致时扩展剩余普通 HTTP 来源，再计算严格多数。
6. 双源冲突时优先扩展来源，不按固定优先级猜测。
7. 最终只剩一个候选时，仍可按现行单源降级规则发布，但不启用跨源自动删除或句序定责。

`candidateSourcePriority` 只应影响首批尝试顺序，不应排除未列出的已映射来源。来源优先级不能覆盖官方硬门槛和多数证据。

## 10. 派生正文与审计

原始快照不得修改。自动净化生成派生内容，并至少记录：

```json
{
  "removalPolicy": "strict_three_source_anchor_bounded_unique",
  "sourceCount": 3,
  "removedLines": [
    {
      "paragraphIndex": 35,
      "content": "待删除的完整水印段",
      "anchorSourceIds": ["source_b", "source_c"]
    }
  ],
  "removalRatio": 0.006,
  "revalidation": {
    "passed": true,
    "officialPreviewOverlap": false,
    "wordCountNotWorse": true,
    "officialAnchorTrusted": true
  }
}
```

正式章节元数据还应记录：

- 参与比较、通过、拒绝和未响应的来源。
- 句级覆盖率、倒退次数和大范围跳转次数。
- 多数参考组。
- 自动删除的完整文本，不能只保留摘要。
- 最终官方预览与字数复核结果。

正常重建从每源 `rawContent` 重新执行精确规则，再用各源派生 `content` 重放多源选择和净化；原始快照不得被多源净化覆盖。

## 11. 历史数据处理

现有真实数据中包含旧候选匹配规则留下的错位快照。迁移时：

1. 不批量删除历史原始快照。
2. 先按官方标题主体和预览重新校准章节身份。
3. 无法确认身份的快照标记为 `rejected_identity_mismatch`，不得进入句级或水印比较。
4. 对已发布章节执行只读回放，先生成拟议选择和拟议删除审计，不立即覆盖正文。
5. 将拟议结果与当前正式正文、官方字数及人工抽样结果比较。
6. 评审通过并完成回放验收后，再允许重建生成新版本。

## 12. 性能边界

真实数据全量运行现有段级诊断超过两分钟，不适合原样放入在线章节热路径。

实现应遵守：

1. 只比较已通过官方门槛且身份确认的候选。
2. 首批最多比较三个来源，冲突时才扩展。
3. 句子指纹随快照保存或按正文哈希缓存，正文未变时不重复切分。
4. 优先在当前章节窗口内处理，不扫描整书。
5. 重建和全书审计使用后台低优先级批次，不阻塞阅读请求。
6. 不引入 AI、消息队列、Redis 或新的外部服务。

## 13. 验证方案

### 13.1 离线回放

使用现有 `天命之上_风月` 快照至少覆盖：

- 正常双源一致章节。
- 正常三源一致章节。
- 第六十八章、第六十九章句序错乱样本。
- 固定列宽换行来源。
- 繁简和异体字差异。
- 标题错位历史快照。
- 单段水印、连续多段水印，以及必须保留的章首/章末单侧差异。
- 合法来源独有正文，验证不会被误删。
- 付费预览和正文截断，验证不会被当成多数参考。

### 13.2 自动化断言

至少验证：

1. 官方预览或字数失败的候选不能进入共识池。
2. 两个正常来源一致、一个错序来源异常时，只拒绝错序章节。
3. 双源冲突不会自动删除或定责。
4. 三源多数支持的锚点间完整水印句可以生成派生正文。
5. 差异内容与官方预览重叠时绝不删除。
6. 删除后官方复核失败时自动撤销派生正文。
7. 强制换行不会产生水印删除。
8. `rawContent`、旧派生版本和完整审计均未被覆盖。
9. 规则回放具有确定性，同一输入产生相同结果和哈希。

### 13.3 上线顺序

1. 已完成句序只读实验和真实订阅数据抽查。
2. 已启用句序异常拒绝。
3. 已启用严格三源、双侧锚点、小范围额外段删除。
4. 自动化回归覆盖双源、繁简、强制换行、比例上限、官方复核撤销和原始快照保留。
5. 后续根据真实订阅审计中的撤销比例决定是否调整阈值，不自动放宽门槛。

## 14. 已确认边界

1. 自动删除必须同时具备可信官方预览和官方字数，缺一时保留原正文。
2. 繁简与异体字转换只用于比较指纹，正式正文保留选中源原文。
3. 双源冲突、章首章末单侧差异、句内差异、连续超过 3 段或总量超过 2% 均不删除。
4. 其他来源只建立共识坐标，不向正式正文补句、拼段或改写。
5. 历史原始快照保留；规则升级通过本地重建生成新的派生正文和审计。

## 15. 本稿建议结论

1. 句级序列校对应正式用于顺序异常检测。
2. 段级结果继续用于定位和审计，不直接承担顺序硬判定。
