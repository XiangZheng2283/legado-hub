# 订阅源快照与官方锚定重构方案

> 状态：已完成（2026-08-02 真实书籍受控验收通过）
> 日期：2026-07-27
> 范围：共享订阅书、第三方正文抓取、官方章节锚定、正文发布、更新与重建
> 替代对象：现有“主源实时取章 -> 候补源补全 -> 行级共识净化”链路

## 当前实施状态

- Phase 1 已完成：数据库 v14、每源快照运行记录、原文/净化正文/净化审计、文件快照和断点续抓。
- Phase 2 核心已完成：官方章节窗口驱动正常订阅；候选正文按当前章节按需抓取并保存快照；已有快照仍须通过官方预览/字数锚定；句级顺序校验可拒绝有双参考证据的错序章节；段级差异仅写入诊断；本地重建会重新净化并从快照重新选择候补正文。
- Phase 3 核心已完成：周期更新刷新官方目录；有待处理新章时同步抓取该窗口的候补正文。历史预读取只允许作为低优先级增强，不能成为订阅前置条件或阻塞新增章节发布。
- 初始预取已完成：源映射完成后的首次订阅给第三方源最多 60 秒先手机会；不同第三方源并行、同书同源串行，超时后无条件进入正式章节处理。

- 本地重建已完成真实验收：不访问网络，重写 3465 条来源快照和 1025 章输出；无官方正文或字数锚点的旧候补全文会撤下可读索引并进入失败重试。

## 1. 目标

订阅以官方目录和章节处理窗口为主线。处理每一章时，按需读取候选源并立即保存其原始快照，再用官方数据校验并发布一份完整正文。

官方源是书籍身份、目录、章节状态、免费全文和付费预览的可信锚点。第三方源是可验证、可回退、但不长期可信的正文候选。任何已发布章节必须完整来自一个源快照，禁止跨源拼接或重排正文。

## 2. 固定原则

1. 订阅书仍是全局共享书；同一本书只建立一份源快照和一份发布正文。
2. 订阅开始时允许读取一次官方详情和目录，以固定书籍身份、章节索引及付费状态；不在此阶段拉取官方章节正文。
3. 第三方源按书独立保存。源映射完成后的首次订阅允许最多 60 秒初始预取；此后抓取进度跟随正常订阅章节窗口推进。原始内容按 `sourceId` 隔离保存，域名仅是记录字段，不作为稳定主键。
4. 每个源章节抓取后立即保留原文并执行现有正则净化；不得覆盖原文，也不得基于跨源差异自动删除正文。
5. 作家说、本章说和段评不在候补源抓取阶段请求。最终正文确定后，才从选定的官方评论链路请求一次作家说。
6. 句级校对只在至少两个顺序一致的参考来源共同证明异常时拒绝当前来源的当前章节，不修改或重排正文，不排除整个源。
7. 段级差异和未知水印只记录诊断；AI 审计和自动删除不纳入本阶段。

## 3. 数据布局

逻辑目录如下，物理根目录由运行时数据目录统一解析：

```text
library/<书名>_<作者>/
  manifest.json
  sources/
    <sourceId>/
      manifest.json
      chapters/
        000001.json
  aggregate/
    chapters/
      000001.json
```

单个第三方章节快照至少包含：

```json
{
  "chapterIndex": 1,
  "title": "第一章",
  "sourceId": "example_com",
  "sourceChapterUrl": "https://...",
  "fetchedAt": "2026-07-27T00:00:00+00:00",
  "rawContent": "抓取原文",
  "content": "正则净化后的正文",
  "contentHash": "...",
  "wordCount": 1234,
  "purifyAudit": []
}
```

`purifyAudit` 记录命中的现有规则、位置、删除文本和规则版本，供重建和回查使用。聚合章节只引用被选中的完整源快照，并记录校验结果、可信度和拒绝的同章快照原因。

## 4. 初始订阅流程

### 阶段 A：身份和源清单

1. 用官方详情和目录确认书名、作者、官方书籍 ID、章节总数、章节标题、VIP 状态和官方字数/预览能力。
2. 搜索并保存可用第三方源的书籍 URL、目录 URL、插件 ID、实际域名和发现时间。
3. 这一步失败时不得创建没有身份锚点的共享书。

### 阶段 B：按章节窗口抓取候选快照

1. 源映射完成后，首次订阅为第三方源提供最多 60 秒初始预取，只抓取正式窗口起点附近最多 20 章，不等待任何来源完成整书下载。
2. 60 秒到期、预取提前完成或没有可预取来源时，立即进入正式章节处理；预取失败和超时不计入正式章节失败。
3. 正式处理优先复用已保存快照；快照不存在时才主动抓取。同一来源的预取和正式请求必须共用同一限流槽，取得槽位后再次检查快照，禁止重复抓同一章。
4. 每个源独立记录已保存章节数、总章节数和失败；一个源失败不能中止其他源或整本书。
5. 不同第三方源允许并行；同一本书的同一来源内部并发默认 1，Browser 来源额外遵守全系统并发 1。
6. 每章按以下顺序处理：保存 `rawContent` -> 应用现有正则净化 -> 清理开头重复章节标题 -> 保存 `content` 与净化审计。
7. 重复标题只允许删除正文开头中、规范化后与目录标题完全相同的一行；不得对全文进行模糊删除。
8. 本阶段不得调用 `chapter_reviews`、作家说、段评或本章说接口。
9. 已保存快照优先复用，但仍必须经过当前官方预览或官方字数锚定；没有官方锚点的历史快照不得直接发布。

### 阶段 C：官方章节锚定与发布

1. 按官方目录顺序处理当前章节窗口；无需等待第三方整书快照完成。
2. 官方免费全文可直接发布为官方正文。
3. 官方付费章节保留预览；第三方候补必须通过标题/序号、预览对齐、长度超过预览以及官方字数范围校验。
4. 通过官方门槛的第三方候补再执行多源句序校验；有双参考证据的错序候选只在当前章节内拒绝，不推广为整源禁用。
5. 选中候补后，发布其完整 `content`，不得与其他来源拼接，也不得按照差异删除其中语句或段落。

### 阶段 D：章末作家说

1. 最终正文已确定后，才通过官方插件的评论能力拉取作家说。
2. 作家说使用现有专用净化规则，单独保存为 `authorNote`，在阅读端章末展示。
3. 评论请求失败不阻塞正文发布，作为独立可重试任务处理。

## 5. 多源结构校对规则

校对输入是各源已完成正则净化并通过官方门槛的 `content`。句级序列用于顺序硬判定，段级差异只用于定位和审计。

### 5.1 句序异常拒绝

正文只为比较生成句子指纹：统一 Unicode 和繁简、去除排版空白与标点，但不修改原始快照或发布正文。匹配位置使用最长递增子序列、错位数和倒退数判断是否持续异常。

- 至少两个其他来源彼此顺序一致，且候选同时与两者发生持续倒退或交叉时，标记该源的该章节为 `rejected_order_mismatch`。
- 该标记只排除当前章节快照；该源仍可参与其他章节和后续更新。
- 单源、双源、二对二冲突、句子不足或覆盖不足时不定责；不得自动重排、拼接或改写正文。
- 审计保存句数、覆盖率、顺序比例、错位数、倒退数和参考来源，实时抓取与本地重建使用同一判定入口。

### 5.2 疑似插入段诊断

若某段只存在于一个源，且前后锚点能在其他源顺序对齐，则记录为 `source_only_segment`。该记录是插件维护证据，不是删除命令。

- 已知水印继续由抓取阶段的现有正则净化处理。
- 未知疑似插入段保存来源、章节、位置、相邻锚点和原文，后续只允许为对应插件补精确 DOM 或正则规则。
- 不得将“其他源没有”直接解释为“水印”。

## 6. 候补发布与降级

1. 三个及以上候补与官方锚点、彼此结构均一致：发布为高可信正文。
2. 两个候补通过官方锚点并相互一致：允许发布，标记双源校验。
3. 一个候补通过官方预览、标题和字数校验：允许发布，标记单源校验。
4. 无候补通过：保留官方预览或失败状态，不发布伪完整正文。
5. 候补数量、校验结果和被拒绝原因必须保存在章节元数据中，供管理页面显示和重建使用。

## 7. 更新、重试与重建

### 7.1 周期更新

1. 每个周期先刷新官方目录。
2. 官方发现新增章节时，对该书所有已记录第三方源刷新目录，并仅抓取新增章节及尾部校验窗口。
3. 已失效源保留历史快照和错误；后续周期继续按退避策略探测，不删除源映射。
4. 可在独立周期重新发现新候补源；新增源的历史全量抓取不得阻塞已有书的新增章节发布。

### 7.2 失败和并发

1. 源级目录失败、章节失败、官方锚定失败和评论失败分别记录并独立重试。
2. 每个源有独立并发和退避；同书同源默认串行、不同第三方源可并行、Browser 来源全系统串行；官方请求保留低并发队列。
3. 失败章节在下一可执行周期优先于普通待处理章节。
4. 正文覆盖继续显示已发布全文、预览、待处理和失败；第三方抓取进度放入候选源列表，在对应来源行底部使用极细进度条展示已保存章节数/该源目录章节数，不再占用独立卡片。

### 7.3 重建

1. 正常重建优先使用本地 `rawContent` 重新执行现有正则净化、段级诊断和发布选择。
2. 只有用户或管理员明确要求“重新抓取”时才访问源站。
3. 重建必须产生新的净化/发布版本，同时保留旧审计信息以支持回滚。

## 8. 实施边界与迁移

1. 以源快照表/索引和文件布局为新的事实来源；旧聚合正文在迁移期间只读保留。
2. 新链路完成一个共享书的快照、锚定和发布后，才切换该书的 Reading 读取目标。
3. 禁止新旧链路同时写同一章节的正式输出。
4. 现有 `aggregate_line_consensus` 的自动删段职责必须移除或降级为只读诊断，不能迁入新流程。
5. 不新增 AI 服务、消息队列、Redis 或新的外部依赖。

## 9. 分阶段验证

### Phase 1：源快照基础

- 订阅创建、候选源按章节窗口抓取、断点续抓、原文/净化后正文/审计记录。
- 定向测试：重试、恢复、重复标题清理、原文不被覆盖。

### Phase 2：官方锚定与发布

- 免费全文、VIP 预览、单源/双源/三源降级、章节级错序排除。
- 定向测试：错误章节不发布、同源其他章节仍可发布、Reading 只读已发布输出。

### Phase 3：增量更新与重建

- 官方目录增量、全部已记录候补源的新增章节同步、失败恢复、本地重建无网络请求。
- 定向测试：连续更新、源恢复、历史快照重建与进度统计。

### Final：完整验证

- 完成上述阶段后运行项目规定的完整 `verify.ps1`。
- 使用至少一本真实连载书做受控验收：检查快照隔离、VIP 预览锚定、错序章节排除、未知插入段审计、增量章节同步和重建回滚。

## 10. 验收标准

1. 每个已记录第三方源都能查询总章节数、已保存章节数、失败状态；每个已抓取章节都能查询原始快照。
2. 任意已发布第三方正文可回溯到唯一的源快照，且不会混入其他源的段落或句子。
3. 官方预览章节不会因候补不足被错误显示为完整正文。
4. 错序只拒绝该源的该章节，不影响该源其他章节。
5. 未知水印只产生审计证据，不触发自动删文。
6. 作家说只在最终章节阶段请求，且不阻塞正文发布。
7. 官方新增章节时，所有已记录候补源都会参与对应增量抓取。
8. 重建可从本地原始快照完成，不默认重新请求第三方或官方站点。
9. 第三方源预读取无论成功、失败或超时，都不能阻塞正常订阅章节窗口推进。

## 11. 2026-08-02 真实书籍受控验收

验收对象为本地已有《天命之上》（风月）的隔离副本。测试只复制目标书籍的数据库行和约 21 MB 文件目录，原始运行库未写入；测试进程同时拦截了 `socket.connect` 与 `socket.create_connection`。

- 输入：1027 章、3465 条来源快照、12 个实际有快照的来源。
- 结果：48 章官方全文、936 章候补全文、41 章官方预览、2 章失败待重试。
- 4 章旧候补正文未通过当前规则：第 126、809 章降级为官方预览；第 718、978 章因缺少官方正文和官方字数锚点撤下可读索引。
- 936 章候补全文全部满足官方预览或官方字数锚点；原有 39 章预览全部保留。
- 3465 个快照文件与数据库一一对应，来源目录隔离、UTF-8 JSON 和 SHA-256 内容哈希一致。
- 段级诊断记录 223 条疑似差异，自动删除 0 条；该次验收未观察到真实错序样本。2026-08-03 已补充三源错序、双源冲突、插入句、繁简换行和本地重建自动化回归。
- 书库完整性扫描结果为 1 本健康、0 个问题；网络尝试次数为 0。
- 重建用时约 312 秒。已缓存处理器实例内的官方插件分类，避免逐章重复解析全部插件元数据；完整插件热更新仍通过新建处理器或重启进程生效。
