# 第三方站点水印采样与插件规则固化方案

> 状态：已完成（阶段 D：补采与第二批规则固化）
> 日期：2026-07-31
> 范围：全部正式第三方插件、站点排行榜样本、混淆水印模板、插件级 `adPatterns`
> 关联评审：`multi-source-sentence-alignment-watermark-review.zh-CN.md`、`watermark-auto-removal-improvement.zh-CN.md`

## 1. 目标

对 `plugins/sources/thirdparty/` 中每个正式插件执行一次可恢复的真实站点采样：

1. 从该站点自身排行榜、热门榜、推荐榜或最近更新榜选择 3 本书。
2. 每本书从完整目录中确定性抽取 50 章，共计划 150 章/站点。
3. 通过插件运行时调用详情、目录和正文，不绕过插件直接编写另一套正文解析器。
4. 保存插件返回的原始章节正文、章节位置、书籍和站点证据。
5. 使用双源/多源同章差异定位水印候选，并使用同源跨章的结构聚类归纳混淆水印家族。
6. 人工确认后，将稳定规则写入对应插件的 `metadata.yaml -> adPatterns` 或已有 `get_ad_patterns()`。

采样阶段只生成候选和证据，不直接修改线上正文，不自动把候选正则写入插件。

## 2. 固定边界

1. 官方预览和官方字数始终是正式正文发布的最终硬门槛。
2. 普通第三方镜像不得新增对外 `explore` capability。采集器可调用插件已经存在的内部排行榜方法；没有该方法时，排行榜发现只能放在诊断侧适配器中。
3. 排行榜适配器只负责产生书籍 URL，不实现详情、目录或正文解析。后三段必须继续走插件。
4. 尊重插件和宿主的并发、超时、代理、Browser 与退避规则。
5. 单站失败不得中断其他站点；每个站点、书籍和章节都有独立状态，可断点续跑。
6. 不使用 AI 自动决定删除规则。算法负责聚类和收集证据，规则批准由人工完成。
7. 不修改或覆盖已有订阅数据、Cookie、插件登录状态和历史采样结果。

## 3. 为什么不能要求完整水印文本重复

混淆水印可能每章变化，例如：

```text
无错版本在读！6=9+书_吧首发本小说
无錯版夲在讀！６．９書吧首發夲小説
正確內容在％六九％書'吧讀
```

采样需要识别的是同一水印家族的稳定结构，而不是等待某个完整句子重复 5 次。

可作为家族证据的特征包括：

- 稳定 token 或其近似形式。
- 全半角、繁简、同形字、插入符号和空白变化。
- 固定 DOM 节点、class、属性或相邻结构。
- 章首、章末或固定正文位置。
- 同章其他来源缺失或只包含其中的作者公共文本。
- 前后正文锚点保持连续。

完全相同的跨章重复只能作为一种辅助证据，不能作为必要条件或单独删除依据。

## 5. 排行榜书籍发现

按以下顺序确定书籍：

1. 插件已有 `explore_groups()` / `explore()`：优先选择 `kind=rank`，其次选择热门、推荐、完本或最近更新组。
2. 插件内部已有 `_search_from_explore()`、排行榜常量或首页书单解析：复用同一实现。
3. 插件没有发现实现：诊断侧为该站点配置排行榜 URL 和最小书籍链接提取规则。
4. 排行榜受 Cloudflare 或登录限制：继续使用插件声明的 Browser、代理或协议访问路径。
5. 仍不可用：标记 `ranking_blocked`，保留失败证据，不以搜索关键词结果代替排行榜。

选择规则：

- 去重后的前三本可完整进入详情和目录的书。
- 目录不少于 50 个可读章节。
- 同站三本书必须是不同 `bookUrl`。
- 优先选择榜单中排名靠前且章节覆盖足够的书，不按书名人工挑选。

## 6. 每本书的 50 章

为覆盖站点模板变化，不固定抓取前 50 章。采用确定性分层抽样：

1. 前部 5 章。
2. 中间区间按固定随机种子抽取 40 章。
3. 尾部 5 章。

固定随机种子由 `sourceId + bookUrl + samplerVersion` 生成。相同目录和版本重复运行应得到相同章节集合。

章节 URL 去重。正文为空、挑战页、付费预览或错误页不计为成功样本，但保留失败状态并继续下一个章节。

## 7. 采集输出

诊断数据写入：

```text
dev-assets/diagnostics/site-watermark-sampling/
  run.json
  progress.jsonl
  <sourceId>/
    source.json
    books/
      <bookKey>/
        book.json
        chapters.jsonl
    candidates.json
    report.md
```

`run.json` 记录采样版本、开始时间、插件版本和参数。`progress.jsonl` 采用追加写入，进程中断后可根据已完成键跳过。

每个章节至少保存：

```json
{
  "sourceId": "example_com",
  "bookName": "示例书",
  "bookUrl": "https://example.com/book/1",
  "chapterIndex": 100,
  "chapterTitle": "第一百章",
  "chapterUrl": "https://example.com/chapter/100",
  "tocCount": 1000,
  "samplePosition": "middle",
  "content": "插件返回的正文",
  "contentLength": 3200,
  "contentHash": "sha256",
  "status": "captured"
}
```

不在报告中保存 Cookie、token、代理凭据或其他秘密。

## 8. 水印候选识别

### 8.1 DOM 证据优先

如果插件能够在正文解析前确认稳定的广告节点或属性，应优先把该结构记录为插件解析证据。稳定 DOM 选择器比正文正则更可靠。

DOM 证据必须证明不会选中普通正文容器。不能因为某个 class 名包含 `content`、`read` 或 `text` 就删除节点。

### 8.2 双源同章差异

同一本书能够在其他插件中定位时，使用标题和官方锚点建立同章坐标，再比较句子序列：

1. 比较前先统一全半角、繁简、空白和常见混淆字符，仅用于指纹。
2. 使用局部句子模糊匹配定位差异区域。
3. 水印可能降低局部相似度，不降低全章身份或官方校验门槛。
4. 双源差异只生成候选，不能单独证明哪一方是水印。
5. 使用 token 包含关系保护两源共有的作者文本，只把额外后缀或前缀列为候选。

### 8.3 同源跨章模板聚类

将该站 150 章中的差异片段按以下特征聚类：

- 规范化 token 序列。
- 稳定 token 的相对顺序。
- 可变区间长度。
- 位置分布。
- 前后锚点类型。
- DOM 位置或节点特征。

模板聚类允许每章原文完全不同。候选正则只能对稳定 token 之间使用有限长度通配，例如 `{0,6}`，禁止无限制 `.*`。

### 8.4 跨源包含否决

若另一来源在同章包含候选文本的公共部分，则公共部分可能是作者留言或版本正文，不能进入水印规则。

示例：

```text
来源 A：（还有更新耶）热门小说
来源 B：（还有更新耶）
```

公共部分 `（还有更新耶）` 必须保留。只有来源 A 的额外后缀 `热门小说` 可以继续接受站点专属规则审查。

## 9. 候选规则分级

### 9.1 可建议批准

同时满足以下证据时，可列为 `recommended`：

- 有稳定 DOM 排除证据；或存在稳定 token 模板。
- 主要位置固定在 head/tail，或包含明确站点标识。
- 通过跨源包含否决。
- 未与官方预览重叠。
- 使用有限边界后不会匹配抽样中的正常正文。
- 至少在该站两本书中观察到同一模板家族；文本不要求全等。

### 9.2 待人工确认

只有单书证据、位置为 inline、稳定 token 较少或反例不足时，标记 `review_required`。

### 9.3 拒绝生成规则

以下候选只保留诊断：

- 无稳定 token、无稳定 DOM 且每次完全随机。
- 只能通过宽泛常用词识别。
- 会匹配正常对话、拟声词或作者留言。
- 必须使用无限通配才能覆盖。
- 双源无法判断哪方缺文或多文。

这类未知水印只能在正式订阅的三源多数、锚点完整条件下按章处理。

## 10. 插件规则固化

仓库已经支持两种插件级入口：

1. `metadata.yaml` 的 `adPatterns`。
2. `Source.get_ad_patterns()`。

优先把短小、声明式、稳定的规则写入 `adPatterns`。只有需要共享已有常量或生成有限变体时才使用 `get_ad_patterns()`。

每个正式插件最终必须留下采样结论：

- 已采集且发现水印：记录样本、反例、批准规则和版本。
- 已采集但未发现水印：明确记录样本覆盖和结论。
- 无法完成采集：记录阻塞阶段、错误和最后探测时间。

不得因为“未发现”而添加宽泛兜底正则。

## 11. 运行与恢复

1. 默认站点串行，单站内部使用插件声明的并发限制。
2. 每完成一章立即追加进度并落盘，不等待整站结束。
3. 重跑时跳过内容哈希和采样版本均一致的成功章节。
4. 失败章节按有限次数退避重试；挑战、封禁和登录错误不密集重试。
5. Browser 站点独立排队，避免并发浏览器占满内存。
6. 支持 `--source`、`--resume`、`--books-per-source`、`--chapters-per-book` 和输出目录参数。

## 12. 阶段验收

### 阶段 A：采集器

- 使用一个普通 HTTP 插件和一个 Browser 插件完成 3 本书 × 50 章。
- 中断后恢复不会重复抓取已成功章节。
- 原始正文未经过宿主全局水印净化。

### 阶段 B：全站采集

- 采样时 30 个插件均产生 `completed`、`partial` 或明确的 `blocked` 状态；已移除插件保留归档结论。
- 每个成功站点可追溯榜单、书籍、目录和章节 URL。
- 总结实际书籍数、章节数、失败阶段和耗时。

### 阶段 C：候选规则

- 每个候选包含模板、变体、位置、书籍数、章节数、异源证据和反例。
- 跨源包含关系已执行。
- 候选不自动写入插件。

### 阶段 D：插件适配

- 人工批准后逐插件写入规则。
- 每条规则必须有命中和反例测试。
- 插件烟测、定向净化测试通过后，再进行完整项目验证。
